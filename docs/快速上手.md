# agent-wiki 快速上手（30 分钟从 0 到第一本书）

> 这份指南把"clone → 跑通 → 看到产出"压缩到 30 分钟。读者画像：会用命令行、有 LLM API key、电脑上有 PDF/EPUB 想喂给 agent。

## 0. 它是什么、不是什么

**它是**：一条 PDF/EPUB → 结构化 wiki 的自动 pipeline。每本书拆成
带溯源锚点的 markdown 页，按概念/实体/主题/源 4 类组织，跨书相同
概念自动合并。每本书 = 一次 git commit，回滚一键。

**它不是**：
- ❌ 一个 RAG 检索系统（不做 embedding、向量索引）
- ❌ 一个聊天 UI（输出是 wiki/*.md，配 obsidian / VS Code 看）
- ❌ 一个云服务（本地跑，调你自己的 LLM）

## 1. 装依赖（5 分钟）

### 系统层

```bash
# macOS
brew install python@3.12 poppler pandoc
# 可选：扫描型 PDF 才需要
brew install ocrmypdf tesseract-lang ghostscript

# Ubuntu/Debian
sudo apt install python3.12 poppler-utils pandoc
sudo apt install ocrmypdf tesseract-ocr-chi-sim ghostscript
```

| 工具 | 干什么 | 必须？ |
|---|---|---|
| `pdftotext`（poppler） | PDF → MD 主路径 | ✅ |
| `pandoc` | EPUB → MD | ✅ |
| `ocrmypdf` | 扫描 PDF OCR | 仅扫描书需要 |
| `tesseract-lang` | OCR 中文支持 | 仅中文扫描书 |

### Python

```bash
git clone https://github.com/OiiOAI/agent-wiki.git
cd agent-wiki
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 验证安装

```bash
bash scripts/run_tests.sh
```

应当看到 `99 passed`。**这一步不调 LLM，纯本地。** 测试不过别继续，pipeline 一定有问题。

## 2. 配 LLM（3 分钟）

```bash
cp .env.example .env
$EDITOR .env
```

`.env.example` 里有 4 套模板，选一套取消注释：

| 选项 | 推荐场景 | 196 本书估算成本 |
|---|---|---|
| **Claude Sonnet 4.5** | 质量优先；有 Anthropic key | $400-600 |
| **Minimax M2.7-highspeed** | 中文书 + 性价比；本项目跑过 | **$104 实测** |
| **OpenAI gpt-4o**（via LiteLLM 代理） | 已有 OpenAI 账号 | $300-500 |
| **本地 vLLM/Ollama**（via 代理） | 离线 / 隐私 | $0（按你的硬件成本） |

只需填 3 个变量：

```bash
ANTHROPIC_API_KEY=sk-...    # 或 Minimax JWT，或代理 key
ANTHROPIC_BASE_URL=https://api.anthropic.com   # 提供方 endpoint
LLM_MODEL=claude-sonnet-4-5                    # 模型名
```

> Pipeline 默认走 Anthropic Messages API 协议。Minimax / OpenAI / 本地
> 都用同一套协议（OpenAI 需要 [LiteLLM](https://github.com/BerriAI/litellm)
> 之类的网关把 OpenAI 协议转成 Anthropic 协议）。换提供方只改 `.env`，
> 不改代码。

## 4. 第一次跑：3 本书试水（10-20 分钟）

```bash
python -m scripts.ingest.auto_ingest \
    --books-dir ~/MyBooks \
    --limit 3 \
    --per-book-cap 1
```

| 参数 | 作用 |
|---|---|
| `--books-dir` | 你的书所在目录 |
| `--limit 3` | 只处理前 3 本，先看效果 |
| `--per-book-cap 1` | 单本最多花 $1，超出 abort |
| `--budget 5` | 整批最多 $5（可选） |

### 看到什么

```
[auto_ingest] 3 pending in state ...
[1/3] atomic-habits ← MyBooks/Atomic Habits.pdf
   Phase A: converting Atomic Habits.pdf
   Phase A done: converter=pdftotext lang=en pages_total=286
   Phase B: chunking 712,503 chars
   Phase B done: 6 chunks
   Phase C: extracting (6 LLM calls incoming)
   ...
   → ok  elapsed 245s  cost $0.2466  pages=38  val_errs=0
```

每本书走 5 个阶段：
- **A**：PDF/EPUB → Markdown（`tmp/md_cache/`，下次重跑会复用）
- **B**：按章节切块
- **C**：每块调一次 LLM 提取结构化 PageCandidate
- **D**：渲染成 wiki 页面 → `tmp/ingest_staging/<book>/`
- **E**：跑 11 条 SOP 不变量校验

⚠️ **此时 wiki/ 还没动**。所有产物在 `tmp/` 下，可以丢、可以重跑。

### 看产出

```bash
ls tmp/ingest_staging/atomic-habits/
# concepts/  sources/

cat tmp/ingest_staging/atomic-habits/concepts/four-laws-of-behavior-change.md
```

每页应当有：
- YAML frontmatter（id, title, type, tags, related）
- `## Summary`（一段话总结）
- `## Key facts`（带 `[raw/...#p43]` 溯源）
- `## Related pages`（指向其他 wiki 页的 `[[...]]` 链接）
- `## Provenance`（主源 + 附加源）

### 看汇总

```bash
cat tmp/ingest_report.md
```

报表含每本书的：状态、chunk 数、产出页数、validation 错误数、成本、
耗时。3 本书应当都是 `status=ok`。

## 5. 落盘：让 wiki/ 真正接收（1 分钟）

```bash
python -m scripts.ingest.commit_batch
```

它做 4 件事：
1. 把 `tmp/ingest_staging/<book>/*.md` 拷到 `wiki/<type>/`
2. 跨书撞 id（同一概念在多本书出现）→ 自动合并 facts/aliases/related
3. 每本书一个 `git commit -m "ingest: <book>"`
4. 末尾重建 `wiki/index.md` + 打 tag `ingest-batch-<date>`

```bash
git log --oneline | head
```

应当看到 4 条新 commit（3 ingest + 1 index rebuild）。
`git tag -l` 看到 batch tag。

### 看 wiki

```bash
ls wiki/concepts/   # 几十页应当出现
cat wiki/index.md   # 全量目录
```

任何一个溯源链接都点回得到原 PDF 的具体页：
```
... [raw/books/health/Spark.pdf#p43]
```
配 [Obsidian](https://obsidian.md) 打开 wiki/ 文件夹，`[[wiki-link]]` 互联效果最好看。

## 6. 出问题怎么办

### LLM 报错 / 超时

`llm_client.py` 自带 3 次重试 + exponential backoff。失败的 chunk 进
`failed_chunks`，那本书 status=`failed`，**下一本继续**。
查 `tmp/ingest_log/<book_stem>.log` 看具体异常。

### 扫描型 PDF（无文本层）

会 fail 到 `requires manual OCR`。两条路：

```bash
# 路径 1：ocrmypdf 救
python -m scripts.ingest.ocr_rescue --timeout-min 30
```

路径 1 不污染 raw/，OCR 后的 PDF 落到 `tmp/ocr_cache/`，wiki 锚点
仍指向原 raw 路径（你点链接还是回原文件）。

```bash
# 路径 2：marker（PyTorch ML，多 GB 内存）
ENABLE_MARKER_OCR=1 python -m scripts.ingest.auto_ingest ...
```

仅在 16GB+ 机器跑。质量比 ocrmypdf 略好但慢一个数量级。

### 中途想停

`Ctrl-C` 即可。脚本捕 SIGINT，把 `tmp/ingest_progress.json` 存盘后
正常退出。下次同样命令直接续跑——已 `ok` 的书自动跳过。

### 全部回滚

```bash
git tag                                # 找到上一个 batch tag
git reset --hard ingest-batch-<date>^  # 回到 ingest 之前
```

`tmp/` 不动 git，但可以 `rm -rf tmp/` 重来。

## 7. 全量跑（无人值守，可过夜）

```bash
nohup python -m scripts.ingest.auto_ingest \
    --books-dir ~/MyBooks \
    --budget 200 \
    > tmp/run.log 2>&1 &
```

进度查询：

```bash
tail -f tmp/run.log
.venv/bin/python -c "
import json
p = json.load(open('tmp/ingest_progress.json'))
ok = sum(1 for b in p['books'] if b.get('status')=='ok')
fail = sum(1 for b in p['books'] if b.get('status')=='failed')
print(f'{ok}/{p[\"total_books\"]} ok, {fail} failed, \${p[\"total_cost_dollars\"]:.2f}')
"
```

参考：本仓库作者跑 196 本（混中英、混学科、含扫描型）实际数据：
- 总耗时 ≈ 24 小时（INGEST_PARALLEL_CHUNKS=4）
- Phase A-G 全跑通：165 本（84%）；扫描型 31 本进 OCR 救援
- LLM 成本 $104（Minimax）+ OCR $15（仅 LLM 部分）
- 最终 wiki/ 产出 9,576 页

## 8. lint 检查 wiki 健康度

跑过几次后定期：

```bash
python -m scripts.lint.wiki_lint              # 11 条不变量 × 全 wiki
python -m scripts.lint.wiki_conflict_scan     # 跨页撞 id / 撞别名
```

输出在 `tmp/lint_report.md` 和 `tmp/conflict_report.md`。

`dangling_link` 错误大量是正常的——它们是 SOP 设计的 outstanding
refs（A 页提到 [[B]]，B 页还没 ingest）。其他类别（`provenance_format`、
`no_unsourced_core_claims`、`frontmatter_schema`）都应当接近 0。

## 9. 维护循环

| 触发 | 命令 |
|---|---|
| 新书放进 ~/MyBooks/ | `python -m scripts.ingest.auto_ingest --books-dir ~/MyBooks` |
| 想强制重跑某本 | `python -m scripts.ingest.rerun_book <book_stem>` |
| 想看撞主题 | `python -m scripts.lint.wiki_conflict_scan` |
| 想审计 wiki 质量 | `python -m scripts.lint.wiki_lint` |
| 上次跑得不好回滚 | `git revert <commit>` 或 `git reset --hard <tag>` |

## 11. 把它当作个人外脑

本项目最初就是为了模仿 Karpathy 的 [LLM Wiki](https://gist.github.com/karpathy/...)
理念。建议工作流：

1. **每周/每月** 把当期读完/扫完的书丢 `~/MyBooks/`，跑一次 ingest
2. 配 [Obsidian](https://obsidian.md) 打开 wiki/，手动微调有疑问的页
3. 想问"X 是什么/跟 Y 啥关系"时，直接全文搜 wiki/ + 让 agent 走
   query mode（参考 `docs/usecases/query-exercise-and-brain.md`）
4. **不要** 删除 raw/ 下的原书——所有页面的溯源链接全都点回它们

> 这个 wiki 越用越值钱。每多 ingest 一本书，所有跨书相同概念都会
> 自动累积更多 facts、更多源——它在变厚而不是变乱。

## 出错先看哪儿

| 症状 | 看这里 |
|---|---|
| `pip install` 报错 | Python 版本（要 3.10+） |
| `bash scripts/run_tests.sh` 失败 | `pytest` / `pypinyin` 没装；重新 `pip install -r` |
| `auto_ingest` 立刻报 `ANTHROPIC_API_KEY missing` | 检查 `.env` 是否有 `cp .env.example .env` 后填 |
| Phase A `requires manual OCR` | 扫描型 PDF；走 §6 的 OCR 救援 |
| Phase C 慢 / `peer closed connection` | LLM API 限流或网络抖动；脚本会自动重试，等就好 |
| 全文很多 `dangling_link` | 正常，SOP outstanding refs |
| `frontmatter_schema` / `provenance_format` 错误 | 真问题，看 `tmp/lint_report.md` 逐条修 |
