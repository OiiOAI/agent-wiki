# Continuous Deployment

## Summary

Continuous deployment is a practice where product changes are released to customers immediately upon completion, rather than bundled into periodic releases. At IMVU, this meant making about fifty changes per day. The practice requires robust automated testing (the 'immune system') to detect and remove defects automatically, analogous to Toyota's andon cord that stops the production line when problems occur.

## Key facts

- At IMVU, whenever a feature was ready to be tested with customers, the team immediately released a new version of the product, with the whole process repeated several times per day for tiny changes. [raw/books/business/The Lean Startup_ How Today's Entrepreneur - Eric Ries.pdf#p176]
- IMVU's immune system automatically removes defective changes, notifies relevant team members, blocks further changes from being introduced, and requires root cause analysis before resuming. [raw/books/business/The Lean Startup_ How Today's Entrepreneur - Eric Ries.pdf#p177]
- Wealthfront practices true continuous deployment including more than a dozen releases to customers every day in an SEC-regulated environment. [raw/books/business/The Lean Startup_ How Today's Entrepreneur - Eric Ries.pdf#p178]
- Three developments are enabling continuous deployment beyond software: hardware becoming software, fast production changes from lean manufacturing, and 3D printing enabling rapid physical prototyping. [raw/books/business/The Lean Startup_ How Today's Entrepreneur - Eric Ries.pdf#p178]
